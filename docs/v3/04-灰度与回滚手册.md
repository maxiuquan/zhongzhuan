# ZhongZhuan v3 · 灰度与回滚手册

> 配套文档：`docs/v3/03-兼容报告.md`（兼容状态）、`docs/v3/02-架构设计与任务分解.md`（设计）、
> `docs/v3/00-交付决策记录.md`（裁定）。
> 需求：R-P0-25（四级灰度）、R-P1-50（兼容报告）。本手册与实现同步，改实现请同步改本文。

## 1. 总开关与默认值

| 项 | 默认 | 说明 |
|---|---|---|
| `responses_bridge.enabled` | `true` | v3 bridge 总开关（`src/zhongzhuan/config/config.py:182`） |
| `responses_bridge.version` | `"v3"` | 目标版本（当前唯一实现） |
| `responses_bridge.rollout.models` | `{}` | model 级灰度映射（model 名 → bool） |
| `responses_bridge.rollout.groups` | `{}` | group 级灰度映射（group 名 → bool） |
| `responses_bridge.rollout.keys` | `{}` | key 级灰度映射（key_id → bool） |

> ⚠️ **当前实现默认开启 v3**。新部署首次接入即走 v3 路径；
> 存量部署若此前依赖 v2 的 Responses 行为，请先阅读 §4 回滚。

## 2. 灰度优先级（代码事实，勿凭文档记忆）

```
环境变量硬覆盖 > model 灰度 > group 灰度 > 全局 enabled > 默认 true
```

- **环境变量硬覆盖**（`src/zhongzhuan/proxy/feature_flags.py:34-48`）：
  `ZHONGZHUAN_RESPONSES_BRIDGE_V3` 或 `RESPONSES_BRIDGE_V3` 命中即返回，**不继续往下评估**。
  合法值：`1/true/yes/on` → 开；`0/false/no/off` → 关；**非法值按「关」fail-closed**。
- **model 灰度**：`requested_model`（请求 `model` 字段）命中 `rollout.models` 键 → 返回该布尔。
- **group 灰度**：`requested_model` 命中 `rollout.groups` 键 → 返回该布尔（注意：按 model 名匹配 group 名）。
- **全局 enabled**：未命中任何灰度键时返回 `config.enabled`。
- **默认 true**：连 config 都没有（测试注入场景）返回 true。

**key 级灰度单独评估**（`feature_flags.py:73-82`）：`v3_key_allowed(key_id)` 在候选 key 过滤时逐个调用，
排除一个 key 不会关闭其余候选 key 的 v3。**环境变量硬覆盖对 key 级同样生效**（同为 `_environment_override`）。

## 3. 灰度配置示例

### 3.1 全量开启（默认）

```yaml
responses_bridge:
  version: v3
  enabled: true
```

### 3.2 只对指定 model 开启

```yaml
responses_bridge:
  enabled: true
  rollout:
    models:
      gpt-5: true        # 该 model 走 v3
      gpt-4o: false      # 该 model 走 v2
```

### 3.3 只对指定 group 开启

```yaml
responses_bridge:
  enabled: true
  rollout:
    groups:
      canary-group: true   # 该 group 的请求走 v3
```

### 3.4 只对指定 key 开启（key 级）

```yaml
responses_bridge:
  enabled: true
  rollout:
    keys:
      3: true    # key_id=3 参与 v3
      7: false   # key_id=7 排除
```

> 注意：key 级是「候选 key 过滤」语义——请求本身仍要过 model/group/全局判断，
> 二者是 AND 关系（请求级 v3_enabled 为真 **且** 至少一个候选 key 被 key 灰度放行）。

## 4. 回滚步骤（秒级）

### 4.1 环境变量回滚（最快，无需改文件重启）

在进程环境设置后**重启服务**（环境变量在进程启动时读取）：

```bash
# Linux / macOS
ZHONGZHUAN_RESPONSES_BRIDGE_V3=0 python -m zhongzhuan --config config.yaml

# Windows (PowerShell)
$env:ZHONGZHUAN_RESPONSES_BRIDGE_V3 = "0"
python -m zhongzhuan --config config.yaml
```

或写入 `.env`（服务启动时加载）：

```dotenv
ZHONGZHUAN_RESPONSES_BRIDGE_V3=0
```

### 4.2 配置文件回滚（持久化）

```yaml
responses_bridge:
  enabled: false
```

然后重启服务使配置生效。

### 4.3 验证回滚生效

```bash
# 1. 发一个 Responses 非流式 create 请求（任意 body），观察响应：
#    - 回滚生效：走 v2 翻译路径（translate 到 Chat/Anthropic），返回翻译后的 Responses 对象
#    - 未生效：仍走 v3（返回 resp_<uuid> 且 store=true 时持久化）
curl -s http://127.0.0.1:PORT/v1/responses \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-5","input":"hi","stream":false}'

# 2. 观察服务日志：v3 分叉点打印的 ctx.v3_enabled / ctx.endpoint
# 3. 检查 /metrics 的 responses_v3_fallback_total{reason="all_keys_excluded"} 是否归零
```

> **行为确认**：回滚后 `POST /v1/responses`（非流式）走 legacy translate 路径，
> `GET/DELETE /v1/responses/{id}` 返回 405（v2 未实现这些端点，见兼容报告 §5 v2/v3 差异表）。
> 若业务依赖 retrieve/delete/cancel/input_items，回滚会**同时失去这些能力**——这是 v2 的固有边界。

### 4.4 灰度失败时的分级处置

| 故障级别 | 症状 | 处置 |
|---|---|---|
| P0（全部异常） | 所有 Responses 请求错误 | `enabled: false` 或 `ZHONGZHUAN_RESPONSES_BRIDGE_V3=0`，重启，全量回 v2 |
| P1（局部异常） | 某 model/group 异常 | 在 `rollout.models/groups` 中把该 model/group 置 false，重启 |
| P2（单 key 异常） | 某 key 异常 | `rollout.keys` 中把该 key_id 置 false，重启（候选池排除） |
| 观察期 | 指标异常（详见 §5） | 先缩灰度再全回滚，避免直接全量 |

## 5. 灰度观察指标

| 指标 | 含义 | 预期 |
|---|---|---|
| `responses_v3_fallback_total{reason="all_keys_excluded"}` | key 灰度把全部候选 key 排除，回退 v2 | 灰度开启期应 >0（说明 key 灰度在拦），全量后归零 |
| `requests_total`（v3 标签） | v3 请求量 | 与灰度比例一致 |
| `heartbeat_total` / `stream_duration_seconds` | 流式健康（v2 路径） | 回滚后恢复正常 |

## 6. 灰度验证清单（上线前逐项勾选）

- [ ] `config.yaml` 的 `responses_bridge` 段与预期一致（版本/开关/灰度键）
- [ ] 环境变量 `ZHONGZHUAN_RESPONSES_BRIDGE_V3` 未残留旧值（或值符合预期）
- [ ] 非流式 create（v3 开启）返回 `resp_<uuid>`，`store=true` 可 retrieve
- [ ] `store=false` 的 create 不落库，retrieve 返回 404
- [ ] 关闭 v3（`enabled: false`）后重启，非流式 create 走 v2 翻译路径，返回对象无 `resp_` 前缀 id
- [ ] 关闭 v3 后 `GET /v1/responses/{id}` 返回 405（v2 边界，符合预期）
- [ ] 重新开启 v3，行为恢复 v3（对称性验证）
- [ ] 全量回归 `pytest tests/ -q` 绿（存量 30+ 测试文件在 v3 关闭时零修改通过，R-P0-25 A4）

## 7. 与 SDK 客户端的兼容提示

- v3 开启时，官方 OpenAI Python/TS SDK 可直接使用全部 6 个端点（见兼容报告）。
- v3 关闭时，仅 `POST /v1/responses` 可用（走翻译路径），SDK 的 retrieve/delete/cancel/input_items
  会收到 405。请在此模式下只发 create 请求。
- 流式 create 在 v3 开启时返回 in_progress JSON（非真实 SSE），SDK 的 stream 轮询逻辑
  可能视为「响应对象」而非事件流——这是本次交付的诚实边界，见兼容报告 §4。
