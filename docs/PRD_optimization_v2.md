# zhongzhuan 优化与 UI 重做 PRD

## 项目名称
`zhongzhuan_optimization_v2` — Python 后端 + 单文件 HTML 前端

## 产品目标
1. **补齐运营能力**：Token 用量统计 + 成本估算 + 令牌配额管理，达到 one-api 的核心运营水平
2. **提升传输效率**：Gzip 压缩 + CORS 支持，减少 60-80% 响应体积，支持浏览器端调用
3. **现代化 UI**：参考 new-api/VoAPI 的 GitHub Dark 风格，侧边栏 + ECharts 数据看板，告别"丑"

## 用户故事
1. 作为运维者，我想在后台仪表盘看到今日请求量/Token 消耗/费用趋势图，而不是只有数字
2. 作为运维者，我想给每个访问令牌设置额度上限和模型白名单，防止某个客户端用超
3. 作为开发者，我想用浏览器 fetch 直接调用代理 API（CORS），且响应是 Gzip 压缩的
4. 作为运维者，我想在后台一键测试某个 key 是否有效，不用 SSH 上去跑脚本
5. 作为运维者，我想定义 `gpt-4` → `qwen-max` 的别名，客户端代码不用改就能切模型
6. 作为运维者，我想 systemd restart 时不中断正在进行的请求（优雅关闭）

## 需求池

### P0（必须）
- **Token 用量统计**：handler 解析上游响应 `usage` 字段，写入 `request_logs.tokens_in/tokens_out`；新增 `model_pricing` 表存模型倍率；后台仪表盘展示今日/7天/30天 Token + 费用趋势
- **令牌配额管理**：`access_tokens` 表扩展 `quota_tokens`（额度上限）/`used_tokens`（已用）/`model_whitelist`（模型白名单）/`expires_at`（到期时间）；proxy auth 中间件请求前校验配额，请求后扣减
- **Gzip 压缩**：proxy 响应启用 aiohttp 内置 gzip 中间件，非流式 JSON 响应压缩
- **CORS 支持**：proxy + admin 添加 OPTIONS 预检处理 + `Access-Control-Allow-*` 头
- **UI 重做**：单文件 HTML，GitHub Dark 配色，侧边栏导航，ECharts 看板，卡片化布局

### P1（重要）
- **Key 测试连通性**：后台「测试」按钮，调用 `/api/keys/{id}/test`，向上游发 `/v1/models` 探测请求，返回延迟和状态
- **模型别名映射**：`models` 表新增 `alias` 字段（逗号分隔多个别名），handler 请求时若 `requested_model` 匹配别名则路由到该模型
- **优雅关闭**：`__main__.py` 注册 SIGTERM 处理，触发 `app.shutdown()` 等待现有请求完成（最多 30 秒）

### P2（可选）
- 已排除：在线充值、兑换码、多机部署、自动发现 IDE 配额
